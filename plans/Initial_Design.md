# PiNGiN — Initial Design Plan

> **PiNGiN** (pronounced "pi engine") — A local-first pi-agent companion that appears next to your cursor on a configurable shortcut, capturing full context and handing it to pi in one shot.

### Pi-agent SDK Capabilities Available

The pi-agent SDK provides:
- `createAgentSession()` — full agent session with event streaming
- `AgentSession.subscribe()` — real-time text/thinking/toolcall deltas
- `ModelRegistry`, `AuthStorage` — model and credential management
- `SessionManager` — persistent session trees with branching
- `SettingsManager` — compaction, retry, transport settings
- `DefaultResourceLoader` — extensions, skills, prompt templates
- `defineTool()` — custom tool definitions
- `createAgentSessionRuntime()` — multi-session runtime for background tasks
- RPC mode (`pi --mode rpc`) — JSONL protocol for subprocess integration

## Architecture Decision: Electron vs Tauri

### Research Summary

| Criteria | Electron | Tauri v2 |
|----------|----------|----------|
| Node.js SDK integration | Native — pi-agent SDK runs directly | Requires Node.js plugin or RPC subprocess |
| Cross-platform | Win/Mac/Linux — mature | Win/Mac/Linux — stable in v2 |
| Binary size | ~150MB | ~3MB (Rust core) |
| Memory | ~100MB baseline | ~15MB baseline |
| Global shortcuts | `globalShortcut` API | `tauri-plugin-global-shortcut` |
| Screen capture | `desktopCapturer` API | Requires Rust FFI or IPC |
| Window management | Mature multi-window API | Good but newer |
| Ecosystem | 10+ years, vast packages | Growing, Rust-centric |
| Dev speed | Fast — all TypeScript | Rust + TypeScript split |
| Security | Larger attack surface | Smaller surface, Rust memory safety |

### Decision: **Electron**

**Rationale:**

1. **pi-agent SDK is Node.js native** — using it directly via `createAgentSession()` gives us full type safety, event streaming, and zero IPC overhead. With Tauri, we'd either need a Node.js plugin (extra complexity) or fall back to RPC mode (subprocess, JSONL parsing, latency).

2. **Screen capture and global shortcuts are first-class** — Electron's `desktopCapturer` and `globalShortcut` APIs are mature and well-documented.

3. **Development velocity** — the entire codebase stays in TypeScript/JavaScript. No Rust compilation pipeline needed.

4. **Multi-window management** — we need a floating companion window, a session history panel, and potentially background session windows. Electron's window management is battle-tested.

5. **Binary size is acceptable** — 150MB is reasonable for a desktop app. We can use `electron-builder` with compression for distribution.

## Core Features

### 1. Global Shortcut & Context Capture

**Shortcut:** Configurable via settings (default: `Cmd/Ctrl+Shift+P` — "Pi")

**Context captured automatically:**

| Context | Linux | macOS | Windows |
|---------|-------|-------|---------|
| Current window title | `xdotool getactivewindow getwindowname` | AppleScript | PowerShell `Get-Process` |
| Selected text | Copy to clipboard trick | AppleScript | Windows clipboard API |
| Browser URL | `xdotool` + browser-specific | AppleScript (Safari/Chrome) | PowerShell |
| Full screenshot | `gnome-screenshot` / `scrot` / `maim` | Electron `desktopCapturer` | Electron `desktopCapturer` |
| Marked region | Drag-select overlay | Drag-select overlay | Drag-select overlay |
| Working directory | `pwd` in shell | Current dir | Current dir |

**Marked region:** Before pressing the shortcut, the user can activate a "mark mode" (e.g., `Cmd/Ctrl+Shift+M`) that lets them drag a rectangle on screen. The region is captured as a screenshot crop.

### 2. Floating Chat Window

- Appears at cursor position (with edge-boundary clamping)
- Always-on-top (`alwaysOnTop: true`)
- Frosted glass / blur effect (native OS compositing)
- Resizable with minimum size (~320px wide)
- Draggable via title bar
- Closes on `Escape` or clicking outside (configurable)

### 3. Chat Interface

**Message rendering:**

- User messages: Right-aligned, accent color background
- Assistant messages: Left-aligned, dark slate background
- Streaming: Text appears character-by-character as it streams from pi-agent

**Foldable sections:**

| Section | Label | Color | Collapsed by default |
|---------|-------|-------|---------------------|
| Thinking | `Thinking...` | Blue (#60A5FA) | Yes (configurable) |
| Tool call | `Calling tool [name]...` | Yellow (#FBBF24) | No |
| Tool result | `Tool result: [name]` | Green (#34D399) | Yes (configurable) |
| Error | `Error` | Red (#EF4444) | No |
| Compaction | `Compacting...` | Orange (#FB923C) | Yes |
| Retry | `Retrying...` | Orange (#FB923C) | Yes |

Each section is collapsible/expandable with a chevron toggle.

### 4. Context Pill (Bottom Bar)

A small pill-shaped bar at the bottom of the chat window showing:

```
[🍔]  Claude Sonnet 4  |  Thinking: High  |  ████████░░ 62%
```

- **Hamburger menu** (🍔): Opens model selector + thinking level picker
- **Model name**: Current model (e.g., "Claude Sonnet 4")
- **Thinking level**: Current level (e.g., "High")
- **Context usage**: Progress bar showing `% / total_size`
  - Green: 0-59%
  - Yellow: 60-79% (configurable, default 60%)
  - Red: 80%+ (configurable, default 80%)

### 5. Background Sessions

**Task classification:**

- **Simple queries** → answered inline in the floating window
  - "translate this", "what is X", "summarize this"
  - Heuristic: if the response is text-only (no tool calls needed), stay inline
  - Actually: we let the user choose. A "push to session" button in the pill.

- **Heavy tasks** → spawned as background sessions
  - "refactor this codebase", "write tests for X"
  - User initiates via "push to session" or auto-routed if tool calls detected

**Session tracking:**

- Each background session is a full pi-agent `AgentSession` with persistent storage
- Sessions are tracked in a list accessible from the hamburger menu
- Sessions can be resumed, aborted, or deleted

### 6. Session History Panel

**Slide-out panel** from the right side, accessible via hamburger menu.

**Layout:**

```

│  Session History                    │
├─────────────────────────────────────┤
│  [Purple]  Cursor Session #1        │
```

- **Purple highlight** (`#A855F7`): Cursor-spawned sessions (inline chat that was pushed to background)
- **Grey highlight** (`#6B7280`): Background sessions (heavy tasks)
- Clicking a session loads it into the chat window

## Technical Details

### Electron Setup

- **Electron v33+** (latest stable)
- **Vite** for renderer bundling (HMR during dev)
- **electron-builder** for packaging
- **Tailwind CSS** for styling
- **React 19** for UI components
- **Zustand** for state management (lightweight, no boilerplate)

### pi-agent Integration

**Inline mode (floating window):**

```typescript
// Create a session for inline chat
const { session } = await createAgentSession({
  sessionManager: SessionManager.inMemory(),
  authStorage,
  modelRegistry,
  model: selectedModel,
  thinkingLevel: selectedThinking,
});

// Subscribe to events for UI updates
session.subscribe((event) => {
  switch (event.type) {
    case "message_update":
      if (event.assistantMessageEvent.type === "text_delta") {
        // Stream text to chat
      }
      if (event.assistantMessageEvent.type === "thinking_delta") {
        // Stream thinking to foldable section
      }
      break;
    case "tool_execution_start":
      // Show "Calling tool [name]..." section
      break;
    case "tool_execution_end":
      // Show tool result section
      break;
    // ... etc
  }
});

// Send prompt with captured context
await session.prompt(buildPromptWithContext(context));
```

**Background sessions:**

```typescript
// Create runtime for managing multiple sessions
const runtime = await createAgentSessionRuntime(createRuntime, {
  cwd: process.cwd(),
  agentDir: getAgentDir(),
  sessionManager: SessionManager.create(process.cwd()),
});

// Spawn a new background session
await runtime.newSession();
const backgroundSession = runtime.session;
```

### Context Capture Implementation

```typescript
// Main process - context capture
interface CapturedContext {
  windowTitle: string;
  selectedText: string;
  browserUrl: string;
  screenshot?: string;       // base64 PNG
  markedRegion?: string;     // base64 PNG
  workingDirectory: string;
  timestamp: number;
}

async function captureContext(): Promise<CapturedContext> {
  const [windowTitle, selectedText, browserUrl, workingDirectory] = await Promise.all([
    getWindowTitle(),
    getSelectedText(),
    getBrowserUrl(),
    getWorkingDirectory(),
  ]);

  const screenshot = settings.captureScreenshot ? await takeScreenshot() : undefined;
  const markedRegion = settings.captureMarkedRegion ? await getMarkedRegion() : undefined;

  return { windowTitle, selectedText, browserUrl, screenshot, markedRegion, workingDirectory, timestamp: Date.now() };
}
```

### Event Flow

1. User presses `Cmd/Ctrl+Shift+P`
2. `shortcut-manager.ts` intercepts, triggers `context-capture.ts`
3. Context is captured (async, ~500ms)
4. `window-manager.ts` creates/shows floating window at cursor position
5. Renderer receives context via IPC, builds prompt
6. User sees captured context summary (collapsible) + input box
7. User types message and presses Enter
8. Prompt is sent to pi-agent via SDK
9. Events stream back: text, thinking, tool calls
10. UI updates in real-time with foldable sections
11. Context pill updates with usage %

## Key Design Decisions

1. **Electron over Tauri** — pi-agent SDK is Node.js native; Electron gives us direct access without IPC overhead or Rust FFI
2. **Zustand over Redux** — lightweight state management, no boilerplate, perfect for this scale
3. **Tailwind CSS** — rapid UI development, easy theming via CSS variables
4. **MkDocs for docs** — simple, Markdown-native, Material theme is polished
5. **electron-builder** — mature packaging for all platforms
6. **Vite** — fast HMR, modern bundler, great TypeScript support
7. **Slate base for dark themes** — consistent, professional, easy to accent-color

## Risks & Mitigations

| Risk | Mitigation |
|------|-----------|
| Context capture fails on some Linux distros | Graceful degradation — skip missing context, log warning |
| pi-agent SDK memory leaks in long sessions | Periodic session recycling; monitor heap |
| Electron binary too large | Use `electron-builder` compression; offer portable download |
| Global shortcut conflicts | Allow user to reconfigure; check for conflicts at startup |
| Screenshot capture slow | Debounce; use async capture with loading indicator |
| Floating window occluded by fullscreen apps | `alwaysOnTop` flag; option to disable |
